# Government engineering handover — future checklist

**Status: template for a later review; no government handover or acceptance has occurred.**

A handover should identify the exact commit/release, intended use, source/licence inventory, architecture/data flows, threat and privacy assessments, provider/model/policy configuration, controls mapped to current official provisions, conformance and evaluation results, deployment/recovery instructions, known gaps and maintainership.

Provide a reproducible public/synthetic demonstration and show allowed, denied, review-required, missing-evidence and unavailable-provider behaviour. Report model portability only once real adapters have run the same application contract.

The receiving agency determines suitability, security/privacy/records obligations, procurement and deployment approvals. This project offers inspectable code, not certification or a mandate to adopt it.
